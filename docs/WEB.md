# WEB — веб-панель истории событий и управления камерами

Локальная панель на **стандартной библиотеке Python** (`http.server`).
Новых зависимостей не нужно. Показывает лица, машины, животных и
оставленные вещи из той же SQLite-базы, что и камера, а также **live-поток**
с камер, рамки объектов и «чертёж лица» по 106 точкам InsightFace.

Если панель запущена **вместе с камерой** (`main.py`), во вкладке «Камеры»
можно смотреть живой поток, запускать и останавливать камеру и делать снимок.
Отдельный процесс панели показывает только статусы.

```
┌────────────────────────────────────────────────────────────┐
│  MLCamera — история событий        ● онлайн   12:34:56     │
├────────────────────────────────────────────────────────────┤
│  [🗂 История] [🎥 Камеры 1/2]                                │
├────────────────────────────────────────────────────────────┤
│  Всего 128   Люди 42   Машины 51   Животные 20   Посылки 15│
├────────────────────────────────────────────────────────────┤
│  [поиск...] [тип ▼] [камера ▼] [период ▼] [Обновить]       │
│                                                            │
│  СЕГОДНЯ, 27 ОКТЯБРЯ                                       │
│  ┌──────────┐ ┌──────────┐ ┌──────────┐                    │
│  │  фото    │ │  фото    │ │  фото    │                    │
│  │ Собака   │ │ A123BC   │ │ Рюкзак   │                    │
│  └──────────┘ └──────────┘ └──────────┘                    │
└────────────────────────────────────────────────────────────┘
```

Вкладка «Камеры»:

```
┌────────────────────────────────────────────────────────────┐
│  Камера-1 (двор)                              ● работает    │
│  25.0 fps · кадров: 18 240 · кадр: только что              │
```

## 1. Быстрый старт

### Вариант А — вместе с камерой

В `config/config.yaml` (он используется по умолчанию) уже стоит:

```yaml
cameras:
  - name: "Ноутбук (веб-камера)"
    source: 0
    enabled: true

web:
  enabled: true
  autostart: true
  host: "127.0.0.1"
  port: 8088
  control: true          # кнопки старт/стоп/снимок
  overlay: true          # рамки объектов на live-потоке
  face_mesh: true        # 106 точек лица
```

Запусти камеру как обычно:

```bash
python main.py
```

Открой **http://127.0.0.1:8088**. Вкладка «Камеры» полностью рабочая:
live-поток, статусы, старт/стоп, снимок и «чертёж лица».

### Вариант Б — отдельным процессом

Можно держать панель запущенной постоянно, даже когда камера перезапускается:

```bash
python scripts/web_panel.py --config config/config.yaml
python scripts/web_panel.py --config config/config.yaml --open
```

В этом режиме панель **только читает** статусы из
`data/db/camera_status.json` (его пишет процесс камеры) и показывает их
во вкладке «Камеры». Кнопки запуска/остановки/снимка отключены: два
процесса не могут управлять одним потоком камеры.

### Флаг `--web`

Принудительно поднять панель вместе с камерой, даже если `autostart: false`:

```bash
python main.py --config config/config.yaml --web
```

> [!NOTE]
> Управление камерами есть только при запуске панели **в процессе камеры**
> (`python main.py` / `python main.py --web`). Если нужны и кнопки, и
> постоянно живущая панель — запускайте `main.py`, а не отдельный
> `scripts/web_panel.py`.

## 2. Настройка

```yaml
web:
  enabled: true
  autostart: true
  open_browser: true    # открыть панель в браузере при старте main.py
  host: "127.0.0.1"     # 0.0.0.0 — доступ из локальной сети
  port: 8088
  title: "MLCamera — история событий"
  token: ""              # пароль; пусто = без пароля
  control: true          # разрешить старт/стоп/снимок из панели
  overlay: true          # рамки объектов и «чертёж лица»
  face_mesh: true        # 106 точек лица InsightFace
  stream_fps: 10         # FPS live-потока в браузере (1–30)
  stream_quality: 70     # качество JPEG (30–95)
```

| Параметр | Значение |
|---|---|
| `enabled` | включает сервер |
| `autostart` | стартовать вместе с `main.py` |
| `open_browser` | сразу открыть панель в браузере |
| `host` | `127.0.0.1` — только этот компьютер; `0.0.0.0` — все интерфейсы |
| `port` | порт, по умолчанию `8088` |
| `token` | если задан — нужен `?token=...` или cookie |
| `title` | заголовок в шапке и вкладке браузера |
| `control` | `false` — панель только смотрит: статусы видны, кнопки отключены |
| `overlay` | рисовать рамки объектов на live-потоке и снимке |
| `face_mesh` | рисовать 106 точек и контур лица |
| `stream_fps` | частота live-потока (меньше — легче CPU и сеть) |
| `stream_quality` | качество JPEG-потока |

> Все эти поля есть и во вкладке **«🛠 Настройки»** — менять файл вручную
> не обязательно. Там же кнопка «Сохранить и применить».

## 3. Доступ с телефона

1. В конфиге:

   ```yaml
   web:
     host: "0.0.0.0"
     port: 8088
     token: "придумай-длинный-пароль"
   ```

2. Перезапусти камеру/панель.
3. Открой на телефоне `http://IP-КОМПЬЮТЕРА:8088/?token=придумай-длинный-пароль`.
4. Сервер поставит cookie — дальше можно открывать просто `http://IP:8088/`.

С телефона доступны и «Камеры»: статусы, старт/стоп и снимок — если панель
запущена через `main.py`. Обязательно ставь `token`, если открываешь в сеть.

> [!WARNING]
> Не выставляй панель в интернет без токена и HTTPS. Лучше:
> - дома — только локальная сеть;
> - VPS — `host: "127.0.0.1"` + SSH-туннель:
>   `ssh -L 8088:127.0.0.1:8088 user@server`;
> - либо reverse proxy (Caddy/Nginx) с HTTPS и токеном.

## 4. Что умеет

- **live-поток MJPEG** с каждой камеры и кнопка снимка;
- рамки объектов и **«чертёж лица»** по 106 точкам InsightFace;
- карточки событий с фото и вырезкой номера;
- фильтры: тип, камера, период (24 ч / 3 дня / 7 дней / всё время);
- поиск по имени, номеру, марке, цвету, классу;
- счётчики за период и график активности по часам;
- группировка по датам;
- клик по карточке — большое фото и детали;
- автообновление каждые 5 секунд (можно выключить);
- «Показать ещё» — постраничная загрузка;
- вкладка «Камеры»: статус, fps, разрешение, аптайм, события за 24 ч;
- запуск и остановка каждой камеры без перезапуска процесса;
- **вкладка «🛠 Настройки»**: все параметры камеры/ИИ/записи/уведомлений,
  редактор списка камер, FPS live-потока и качество JPEG, сохранение в
  `config/config.yaml` и перезапуск камер;
- вкладка «Система»: версия, БД, диск, возможности, таблица камер, API;
- тёмная адаптивная тема и горячие клавиши `1/2/3/4`.

## 5. API

Все ответы — JSON в UTF-8. Пути к файлам наружу **не отдаются**, только
`type` + `id`; фото запрашивается отдельным маршрутом.

### `GET /api/events`

| Параметр | По умолчанию | Описание |
|---|---|---|
| `kind` | `all` | `all`, `face`, `car`, `animal`, `package`, `object` |
| `camera` | все | точное имя камеры |
| `q` | — | поиск по имени/номеру/марке/классу |
| `hours` | `24` | период в часах; `0` — всё время |
| `limit` | `30` | 1…200 |
| `offset` | `0` | смещение |

```bash
curl "http://127.0.0.1:8088/api/events?kind=package&hours=168&limit=20"
```

```json
{
  "events": [
    {
      "type": "package", "id": 17, "ts": 1761570000.0,
      "camera": "Камера-1 (двор)", "title": "Рюкзак",
      "subtitle": "оставленная вещь · без движения 65 с",
      "score": 0.91, "label": "backpack",
      "has_image": true, "has_crop": true
    }
  ],
  "has_more": false, "limit": 20, "offset": 0
}
```

### `GET /api/stats`

```bash
curl "http://127.0.0.1:8088/api/stats?hours=24"
```

```json
{
  "hours": 24, "total": 128,
  "faces": 42, "unknown": 7, "cars": 51,
  "animals": 20, "packages": 15,
  "by_camera": [{"camera": "Камера-1 (двор)", "cnt": 90}],
  "last_ts": 1761570000.0
}
```

### `GET /api/cameras`

```bash
curl "http://127.0.0.1:8088/api/cameras"
```

```json
{
  "controllable": true,
  "stale": false,
  "updated_at": 1761570000.0,
  "cameras": [
    {
      "index": 0, "name": "Ноутбук (веб-камера)", "enabled": true,
      "status": "running", "alive": true, "fps": 30.0,
      "proc_fps": 12.5, "frames": 18240, "last_frame_ts": 1761570000.0,
      "has_image": true, "width": 1280, "height": 720,
      "source_kind": "webcam", "recording": false, "recording_mode": "events",
      "started_at": 1761569000.0, "uptime": 1000.0,
      "events_24h": 7, "last_event_ts": 1761569900.0, "error": ""
    }
  ]
}
```

`status`: `starting`, `running`, `stopping`, `stopped`, `error`.
`source_kind`: `rtsp`, `http`, `webcam`, `file` — без логинов и паролей.
`proc_fps` — реальная скорость обработки, `fps` — паспортная частота потока.
`controllable: false` — панель запущена отдельно, доступен только просмотр.
`stale: true` — процесс камеры давно не обновлял `camera_status.json`
(больше 15 секунд): статусы могли устареть.

### `GET /api/cameras/snapshot`

```bash
curl -o frame.jpg "http://127.0.0.1:8088/api/cameras/snapshot?index=0"
curl -o frame.jpg "http://127.0.0.1:8088/api/cameras/snapshot?index=0&quality=95&download=1"
```

Свежий JPEG последнего кадра. Параметры: `quality` (1…95), `download=1` —
`Content-Disposition: attachment` с именем файла. `404` — камера ещё не дала
кадров, `409` — панель запущена отдельно от камеры.

### `GET /api/cameras/stream`

```html
<img src="/api/cameras/stream?index=0&fps=10&quality=70">
```

MJPEG-поток (multipart/x-mixed-replace) с рамками и «чертежом лица».
Параметры: `index`, `fps` (1…30), `quality` (1…95). `409` — нет доступа к
камере. Поток не держит камеру: панель берёт последний обработанный кадр.

### `GET /api/timeline`

```bash
curl "http://127.0.0.1:8088/api/timeline?hours=24&buckets=24"
```

Массив столбцов для графика: `ts`, `total`, `face`, `car`, `animal`,
`package`; плюс `max`, `hours`, `buckets`.

### `GET /api/system`

Версия, аптайм, размер БД, свободное место на диске, число камер,
`controllable` и список включённых возможностей (`features`: лица, машины,
объекты, запись, превью, движок номеров).

### Управление камерой (POST)

Только когда панель работает в процессе камеры и `web.control: true`.

| Маршрут | Действие |
|---|---|
| `POST /api/cameras/start?index=0` | запустить камеру |
| `POST /api/cameras/stop?index=0` | остановить камеру |
| `POST /api/cameras/start_all` | запустить все |
| `POST /api/cameras/stop_all` | остановить все |

```bash
curl -X POST -H "X-MLCamera: 1" "http://127.0.0.1:8088/api/cameras/stop?index=0"
curl -X POST -H "X-MLCamera: 1" "http://127.0.0.1:8088/api/cameras/start?index=0"
```

Ответ:

```json
{"ok": true, "message": "", "cameras": [{"index": 0, "status": "stopped", "...": "..."}]}
```

Ошибки: `403` — нет заголовка `X-MLCamera` или чужой `Origin`;
`409` — камера уже запущена/остановлена либо управление недоступно;
`400` — не указан `index`; `404` — нет такого действия.

> [!IMPORTANT]
> POST-запрос обязан содержать заголовок `X-MLCamera: 1`. Это защита от
> CSRF: браузер не может отправить такой запрос с чужого сайта без
> preflight. Дополнительно, если передан `Origin`, его хост должен
> совпадать с `Host` панели.

После остановки всех камер процесс `main.py` **не завершается**, пока
работает панель: камеру можно запустить снова, модели остаются в памяти.

### `GET /api/settings` и `POST /api/settings`

Отдают и сохраняют **весь** `config/config.yaml`: поля по разделам, список
камер, текущий FPS потока.

```bash
curl "http://127.0.0.1:8088/api/settings"

curl -X POST -H "X-MLCamera: 1" -H "Content-Type: application/json" \
     -d '{"values":{"camera.fps":15,"web.stream_fps":8},"restart":true}' \
     "http://127.0.0.1:8088/api/settings"
```

Ответ на сохранение:

```json
{"ok": true, "message": "камеры перезапускаются…", "restarted": true,
 "config_path": ".../config/config.yaml", "settings": {"values": {…}}}
```

Если поле вне допустимого диапазона, приходит `400` и список ошибок.
Перед записью создаётся `config.yaml.bak`. Перезапуск камер после сохранения
доступен только когда панель запущена в процессе камеры (`web.control: true`);
отдельный процесс панели просто сохранит файл.

### `GET /media`

```bash
curl -o dog.jpg "http://127.0.0.1:8088/media?type=animal&id=17"
curl -o plate.jpg "http://127.0.0.1:8088/media?type=car&id=8&crop=1"
```

`type`: `face`, `car`, `animal`, `package`. Файл отдаётся только если он
лежит внутри `storage.events_dir` (`data/events/`), иначе `403`.

### `GET /health`

```json
{"ok": true}
```

### Токен в API

Если задан `web.token`:

```bash
curl -H "X-Token: пароль" "http://127.0.0.1:8088/api/events"
# или
curl "http://127.0.0.1:8088/api/events?token=пароль"
```

## 6. Безопасность

- сервер отдаёт только файлы из `data/events/`;
- идентификаторы событий — числа, произвольный путь подставить нельзя;
- включены `X-Content-Type-Options`, `X-Frame-Options`, `Referrer-Policy`,
  CSP;
- нет загрузки файлов, нет выполнения команд; изменения — только
  `POST /api/cameras/*`;
- POST требует заголовок `X-MLCamera: 1` и совпадающий `Origin` — защита
  от CSRF;
- токен сравнивается через `secrets.compare_digest`;
- cookie — `HttpOnly`, `SameSite=Lax`;
- `web.control: false` полностью выключает кнопки и POST-маршруты;
- `camera_status.json` содержит только имена камер, статусы и счётчики —
  без логинов, паролей и путей RTSP.

Ограничения:

- это **не** многопользовательская система с ролями;
- HTTP без TLS: для интернета ставьте reverse proxy с HTTPS;
- база и фото не шифруются — это локальный инструмент.

## 7. Автозапуск на сервере (systemd)

```ini
# /etc/systemd/system/mlcamera-web.service
[Unit]
Description=MLCamera web panel
After=network.target

[Service]
WorkingDirectory=/opt/MLCamera
ExecStart=/opt/MLCamera/.venv/bin/python scripts/web_panel.py --config config/config.yaml
Restart=always
User=mlcamera

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now mlcamera-web
```

## 8. Диагностика

| Симптом | Решение |
|---|---|
| `Address already in use` | занят порт — смени `web.port` или останови старый процесс |
| Панель пустая | камера пишет в другую БД — проверь `database.path` |
| Фото не открываются | проверь `storage.events_dir` и права на чтение |
| `401` | задан `web.token`; добавь `?token=...` |
| С телефона не открывается | `host: "0.0.0.0"`, порт открыт в firewall, телефон в той же сети |
| Кнопки камер серые | панель запущена отдельно — используй `python main.py --web` |
| `403` на POST | не передан заголовок `X-MLCamera: 1` (curl) или чужой `Origin` |
| `409` при старте | камера уже запущена/останавливается — обнови статус |
| Камера в статусе `error` | смотри текст ошибки в карточке и лог `data/logs/camera.log` (RTSP, логин, сеть) |
| После смены конфига ничего не изменилось | перезапусти камеру/панель |
