# DEPLOYMENT — развёртывание на сервере (VPS ~300 ₽)

Гайд без воды: **что заполнить, где взять значения, куда их вписать** и как всё
загрузить на сервер. Есть два пути — **автоматический** (GitHub + CI/CD) и
**ручной** (команды). Рекомендую автоматический.

> Как найти IP камеры и как сделать, чтобы VPS достучался до домашней камеры
> (VPN / проброс порта) — читай **docs/VPS_CAMERAS.md**.

---

## Часть 1. Что вообще нужно заполнить (список из 5 вещей)

| № | Что заполняешь | Где взять значения | Куда писать |
|---|---|---|---|
| 1 | IP сервера | Панель хостинга VPS | GitHub-секрет `SERVER_IP` (или в команды scp/ssh) |
| 2 | Пароль/логин сервера | Панель хостинга VPS | GitHub-секрет `SERVER_USER`, `SERVER_PASSWORD` |
| 3 | Ссылки на камеры (RTSP) | приложение камеры + IP в локальной сети | `config/config.yaml` → `cameras` |
| 4 | Telegram токен + chat_id | @BotFather и @userinfobot | `config` → `notify.telegram` |
| 5 | Секретный topic для пуша | придумай сам | `config` → `notify.push.topic` + приложение ntfy |

> Есть ещё 6-е: фотки семьи → папки `data/datasets/raw/<имя>/` (см. docs/DATASET.md).

## Часть 2. Подробно про каждый пункт

### 2.1 и 2.2 — IP и пароль сервера

Ты арендуешь VPS (напр. **Timeweb Cloud**, **VDSina**, **Aeza**, от 200-400 ₽/мес).
После создания сервера в личном кабинете будут:

- **IP-адрес** — вида `185.23.45.67`
- **Логин** — обычно `root` (или `ubuntu`, `debian`)
- **Пароль** — или SSH-ключ

Проверь, что сервер доступен с твоего компьютера:

```bash
# Windows: открой PowerShell и выполни
ssh root@185.23.45.67
```

Пароль попросят при первом входе. Если ошибка про ключи — просто `yes`.

### 2.3 — Камеры (RTSP-ссылки)

У тебя камеры стоят **дома**. Чтобы сервер (в интернете) мог к ним подключиться:

1. В приложении камеры (Mi Home, Hik-Connect, Ezviz...) найди раздел
   «О камере / Сетевые настройки» → там **IP камеры** (напр. `192.168.1.100`)
   и **логин/пароль** (учётка администратора, не от Wi-Fi!).
2. Включи **RTSP** (в некоторых камерах это «Включить протокол RTSP»).
3. Проверь ссылку у себя на ПК в VLC: Файл → Открыть сетевой поток →
   вставь `rtsp://ЛОГИН:ПАРОЛЬ@192.168.1.100:554/stream1`.
   Если играет — ссылка верная.
4. Дальше впиши её в конфиг (см. Часть 3).

**Как сервер из интернета увидит твою домашнюю камеру?** Три способа:

- **A (проще всего):** роутер умеет VPN — подними **WireGuard/OpenVPN** на роутере
  или на старом компе дома. Тогда сервер и камеры — «в одной сети», в RTSP
  пишется домашний IP камеры.
- **B:** Пробрось порт 554 на роутере на камеру (Проброс портов → внешний 554 →
  внутренний IP камеры) и в RTSP пиши **внешний** IP дома (узнай на 2ip.ru).
  ⚠️ Это открывает камеру наружу — поставь надёжный пароль камеры!
- **C:** Самый простой для начала — запусти проект **на домашнем компе** (версия
  для ПК, Ryzen 5600 тянет), а VPS пока не нужен. Модель та же.

### 2.4 — Telegram

1. В Telegram найди бота **@BotFather** → отправь `/newbot` → придумай имя →
   получишь **токен** вида `123456789:AAE...`.
2. Найди **@userinfobot** → нажми Start → он пришлёт твой **chat_id** (число).
3. Впиши оба значения в конфиг (Часть 3).

### 2.5 — Push на Android (ntfy)

1. Поставь приложение **ntfy** (Play Market / F-Droid).
2. Придумай секретный topic: `my_camera_7f3a91x` (не дели ни с кем).
3. Впиши его в конфиг → `notify.push.topic`.
4. В приложении ntfy: подписка → ввести свой topic → готово.

## Часть 3. Куда писать: файл `config/config.yaml`

Открой **`config/config.yaml`** в любом редакторе (VS Code, Блокнот) и замени
только строки с пометками `-->`:

```yaml
people:
  names:
    я: "Алексей"            # --> имя, которое увидишь в уведомлениях
    мама: "Ольга"
    папа: "Сергей"
    сестра1: "Аня"
    сестра2: "Катя"

cameras:
  - name: "Камера-1 (двор)"
    source: "rtsp://admin:password@192.168.1.100:554/stream1"   # --> СВОЯ ссылка
    enabled: true
  - name: "Камера-2 (ворота)"
    source: "rtsp://admin:password@192.168.1.101:554/stream1"   # --> СВОЯ ссылка
    enabled: false          # --> true, когда включишь камеру

notify:
  telegram:
    bot_token: "123456789:AA..."   # --> свой токен
    chat_id: "123456789"           # --> свой id
  push:
    topic: "my_camera_unique_secret_topic"   # --> свой topic
```

> Прямые пути ко всем строкам (что, где и зачем) — в файле
> **`config/config.yaml`** — это тот же конфиг с подробными
> комментариями «замени на...».

Сохрани файл. Всё — конфиг готов.

## Часть 4. Загрузка на сервер

### Путь А — АВТОМАТИЧЕСКИ (GitHub Actions, рекомендую)

Раз в неделю что-то меняешь — просто пушишь код, всё ставится само.

1. Заведи репозиторий на GitHub (создай новый repo, пустой).
2. Открой терминал в папке проекта и залей:
   ```bash
   git init
   git add .
   git commit -m "MLCamera v1"
   git remote add origin https://github.com/ТВОЙ_ЛОГИН/ml_camera.git
   git push -u origin main
   ```
3. В GitHub открой **Settings → Secrets and variables → Actions → New secret**
   и создай **4 секрета**:

   | Имя секрета | Значение (пример) |
   |---|---|
   | `SERVER_IP` | `185.23.45.67` |
   | `SERVER_USER` | `root` |
   | `SERVER_PASSWORD` | пароль сервера |
   | `CONFIG_YAML` | **весь текст** файла `config/config.yaml` (открой файл, Ctrl+A, Ctrl+C, вставь) |

4. Пуш в main → GitHub сам: протестирует → соберёт образ → по SSH зайдёт на
   сервер (по IP и паролю из секретов) → поставит Docker (если нет) → зальёт
   твой `CONFIG_YAML` как `config.yaml` → запустит контейнер.
5. Проверка:
   ```bash
   ssh root@185.23.45.67
   docker ps                # контейнер ml_camera должен быть Up
   docker logs -f ml_camera # логи
   ```

### Путь Б — ВРУЧНУЮ (команды)

1. Упакуй проект:
   ```bash
   python scripts/make_release_zip.py     # -> dist/ml_camera_<дата>.zip
   ```
2. Залей на сервер:
   ```bash
   scp dist/ml_camera_20260813_1215.zip root@185.23.45.67:/root/
   ```
3. Разверни (ставит Docker, распаковывает, собирает, запускает):
   ```bash
   ssh root@185.23.45.67 'bash -s' < scripts/deploy_server.sh
   ```
4. Отредактируй конфиг на сервере:
   ```bash
   ssh root@185.23.45.67
   nano ~/ml_camera/config/config.yaml   # вставь свои RTSP, telegram, ntfy
   # Ctrl+O (сохранить), Ctrl+X (выйти)
   cd ~/ml_camera && docker compose -f docker-compose.prod.yml up -d --build
   ```

## Часть 5. После деплоя

- **Лица**: собери датасет НА КОМПЬЮТЕРЕ (удобнее), потом перенеси папку
  `data/datasets` на сервер (scp), либо датасеты можно готовить прямо на сервере.
  Узнать как — docs/DATASET.md.
- **События** лежат в `~/ml_camera/data/events/`, база в
  `~/ml_camera/data/db/ml_camera.db`.
- **Логи**: `docker logs -f ml_camera`.
- **Обновление**: `git push` (если GitHub) или `git pull && docker compose
  -f docker-compose.prod.yml up -d --build` (если вручную).

## Часть 6. Хватит ли сервера за 300 ₽?

- 1-2 vCPU, 1-2 ГБ RAM — да, если:
  - конфиг VPS (`config.yaml`) с малыми моделями (`yolov8n`, `buffalo_s`,
    `tesseract`);
  - включена детекция движения (`motion.enabled: true`) — модели работают
    только при шевелении;
  - 1-2 камеры.
- Не включай на VPS: `easyocr`, `preview`, `recording`, `brand_enabled`.
- Для 3+ камер бери 4 vCPU / 4 ГБ (500-700 ₽).
