# VPS — запуск на сервере + доступ к домашним камерам

Три больших вопроса, на которые отвечает этот файл:

1. **Как найти IP камеры** и проверить RTSP-ссылку.
2. **Будет ли камера доступна с VPS** (сервер в дата-центре, камера дома).
3. **Как запустить проект на VPS** — все способы и команды.

---

## 1. Как узнать IP камеры (домашняя сеть)

Камера живёт в твоей домашней сети и имеет адрес вида `192.168.1.100`.
Найти его можно любым из способов:

### Способ А — фирменное приложение камеры (проще всего)
- Mi Home / Xiaomi Home: камера → «Настройки» → «Сведения об устройстве»
  (или «О камере») — там **IP-адрес** и «Учётная запись RTSP».
- Hik-Connect / Ezviz: «Устройство» → «Сетевые настройки» → IP.
- TP-Link Tapo / Dahua / Reolink: аналогично, «Device info / Network».
- Если не показывает IP — в тех же настройках открой **вкладку «Сеть»**.

### Способ Б — через роутер
1. Открой веб-интерфейс роутера: обычно `192.168.1.1` или `192.168.0.1`
   (напечатано на наклейке роутера).
2. Найди раздел «Подключённые устройства» / «DHCP» / «LAN» / «Список клиентов».
3. Ищи устройство с именем камеры (Xiaomi, HIKVISION, DAHUA...) — напротив будет IP.

### Способ В — сканером сети
- Поставь на телефон **Fing** (или на ПК **Advanced IP Scanner**), запусти
  скан — увидишь все устройства: IP, MAC, имя производителя. Камеры обычно
  называются по вендору (Hikvision, Xiaomi и т.д.).

### Логин и пароль камеры
RTSP-ссылка требует **логин и пароль администратора камеры** (не от Wi-Fi!):
- обычно это то, что ты задавал при первом включении камеры в приложении;
- или заводские admin/пароль с наклейки;
- у многих (Hikvision) нужно создать «учётную запись для стороннего доступа»
  (проверь в настройках камеры).

### Проверка RTSP-ссылки на ПК
Открой **VLC** → «Медиа» → «Открыть сетевой поток» → вставь:

```
rtsp://ЛОГИН:ПАРОЛЬ@192.168.1.100:554/stream1
```

Если пошло видео — ссылка верная, её и пишем в конфиг.
Типовые пути: Xiaomi/большинство `stream1`, Hikvision `Streaming/Channels/101`,
Dahua `cam/realmonitor?channel=1&subtype=0`.

## 2. Будет ли камера доступна с VPS?

**Короткий ответ: по умолчанию НЕТ — нужно одно из двух решений ниже.**

Почему: VPS стоит в дата-центре, камера — дома за роутером. У роутера
«серый» IP (NAT), твоя камера `192.168.1.100` видна только внутри дома.
VPS по адресу `192.168.1.100` дотянуться не может — это чужой адрес в облаке.

### Решение 1 — VPN: VPS и камера «в одной сети» (рекомендую)
Подними **WireGuard** так, чтобы у VPS появился доступ к домашней сети.

- **Вариант 1а: роутер с WireGuard.** Многие роутеры (Keenetic, Mikrotik,
  Asus/OpenWrt) умеют WireGuard. Создай site-to-site туннель:
  - домашняя сторона — сеть `10.0.0.0/24`, где видно камеры;
  - VPS — второй пир этого туннеля, получает доступ в `10.0.0.0/24`.
  - Тогда в конфиге пишем `source: "rtsp://ЛОГИН:ПАРОЛЬ@10.0.0.100:554/stream1"`
    (IP камеры в VPN-сети).
- **Вариант 1б: домашний ПК/одноплатник как «мост».** Если роутер не умеет —
  поставь WireGuard на постоянно включённый домашний комп (или Orange Pi/старый
  ноут) в той же сети, что и камеры, и пробрось в туннель подсеть камер.
- Как настроить WireGuard на VPS: `apt install wireguard`, файл `/etc/wireguard/wg0.conf`.
  Примеры конфигов — в интернете «WireGuard site-to-site», настройка разовая (~30 мин).

**Плюсы:** безопасно, камеры не торчат в интернет, работает с любым числом камер.

### Решение 2 — проброс порта на роутере (проще, но рискованнее)
1. В роутере найди «Проброс портов» / «Virtual Server» / «Port Forwarding».
2. Правило: внешний порт `554` (и, если камеры RTSP/ONVIF, может понадобиться
   и UDP `554`) → внутренний IP камеры `192.168.1.100:554`.
3. Узнай внешний IP дома: `2ip.ru` → напиши его в RTSP-ссылку:
   `rtsp://ЛОГИН:ПАРОЛЬ@ВНЕШНИЙ_IP:554/stream1`
4. ⚠️ Камера будет видна из интернета всем. Обязательно:
   - надёжный пароль камеры;
   - не используй заводские пароли;
   - лучше ограничить проброс по IP-адресу VPS (если роутер умеет).

**Плюсы:** быстро. **Минусы:** открываешь камеру наружу; провайдер может давать
«серый» IP (тогда нужен DDNS, например no-ip).

### Решение 3 — обойтись без VPS
Если запустить **ПК-версию на домашнем компе** (Ryzen 5600 — с запасом),
никакой доступ из интернета не нужен: программа и камеры в одной сети.
VPS пригодится только когда хочется работать 24/7 без включённого компа.

### Как проверить, что VPS «достучался» до камеры
Зайди на VPS и выполни:

```bash
# 1) порт 554 открыт?
nc -zv 10.0.0.100 554          # (или внешний IP при пробросе)
# 2) RTSP-поток доступен? (ffprobe из ffmpeg)
ffprobe -rtsp_transport tcp rtsp://ЛОГИН:ПАРОЛЬ@10.0.0.100:554/stream1 2>&1 | head
# 3) если ffprobe показал метаданные видео — доступ работает
```

Дальше этот же URL пишется в `config/config.yaml` → `cameras[].source`.

## 3. Как запустить на VPS

### Вариант А — автоматически через GitHub (рекомендую)
1. Залить код: `git init && git add . && git commit -m v1 && git push -u origin main`.
2. В репозитории: **Settings → Secrets → Actions → New secret** — создать 4 секрета:
   - `SERVER_IP` — IP сервера (`185.23.45.67`);
   - `SERVER_USER` — `root`;
   - `SERVER_PASSWORD` — пароль от сервера;
   - `CONFIG_YAML` — **весь текст** `config/config.yaml` (Ctrl+A, Ctrl+C, вставить),
     где уже прописаны: доступный URL камеры, токен, chat_ids, ntfy topic.
3. `git push` в `main` → GitHub сам: тесты → сборка Docker-образа → по SSH
   ставит Docker → кладёт твой `CONFIG_YAML` → запускает контейнер.
4. Обновления — просто `git push` заново.

### Вариант Б — вручную
```bash
# у себя на ПК:
python scripts/make_release_zip.py                    # dist/ml_camera_*.zip
scp dist/ml_camera_*.zip root@185.23.45.67:/root/

# на сервере — разворот одной командой (ставит Docker, распаковывает, запускает):
ssh root@185.23.45.67 'bash -s' < scripts/deploy_server.sh

# правим конфиг под себя (доступный URL камеры, токен, chat_ids, topic):
ssh root@185.23.45.67
nano ~/ml_camera/config/config.yaml
cd ~/ml_camera && docker compose -f docker-compose.prod.yml up -d --build
```

### Вариант В — если ставишь не в Docker, а в venv прямо на сервере
```bash
apt install -y python3.10-venv tesseract-ocr tesseract-ocr-rus libgl1 libglib2.0-0
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
nano config/config.yaml          # свои значения
.venv/bin/python main.py --config config/config.yaml
```
> Для запуска 24/7 добавь systemd-юнит или `nohup`; проще всё же Docker.

### Команды проверки на сервере
```bash
docker ps                                   # контейнер ml_camera Up?
docker logs -f ml_camera                    # логи в реальном времени
docker exec ml_camera python scripts/self_check.py    # самопроверка ВСЕХ модулей
ls ~/ml_camera/data/events/                 # снимки событий
docker exec ml_camera python scripts/show_events.py   # последние события из БД
```

## 4. Чек-лист запуска с VPS

- [ ] Сервер: Ubuntu 22.04, 1-2 vCPU / 1-2 ГБ / 10 ГБ (для 3+ камер — 4 vCPU / 4 ГБ).
- [ ] VPS умеет достучаться до камеры: WireGuard ИЛИ проброс порта (проверено `nc`/`ffprobe`).
- [ ] В `config/config.yaml`:
  - `cameras[].source` = доступный RTSP-URL;
  - `people.names` = имена = папки в `data/datasets/raw/`;
  - `notify.telegram.bot_token` + `chat_ids` (кому слать «кто пришёл»);
  - `notify.push.topic` (для пушей на Android через ntfy);
  - `notify.delete_images_after_send: true` (фото удаляются после отправки);
  - `recording.enabled: false` (на VPS видео не пишем).
- [ ] Датасет лиц залит на сервер в `~/ml_camera/data/datasets/raw/`
      (собери на ПК, залей `scp`, запусти `collect_faces.py` и `register_faces.py`).
- [ ] `python main.py --self-test` → тестовое уведомление пришло.
- [ ] `python scripts/self_check.py` → 0 ошибок.
- [ ] `docker logs -f ml_camera` → «Поток камеры ... запущен», без `ERROR`.
